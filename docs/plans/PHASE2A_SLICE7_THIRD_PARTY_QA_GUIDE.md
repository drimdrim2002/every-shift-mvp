# Phase2A Slice7 제3자 QA 실행 가이드

작성일: 2026-04-02  
대상: 개발자가 아닌 QA/기획/운영 검증자

## 1) 이 문서로 무엇을 확인하나요?

이 문서는 `Slice7: Step5 Review Hub Shell and Data Plumbing`만 확인합니다.

확인 항목은 아래 6개입니다.

1. Step5 상단에 `버전 비교` 영역이 항상 보이는지
2. `미리보기`와 `선택됨`이 서로 다른 개념으로 보이는지
3. 버전 카드를 클릭하면 `미리보기`만 바뀌고 `선택됨`은 그대로인지
4. `이 버전을 선택` 버튼을 눌렀을 때만 `선택됨`이 바뀌는지
5. `?version=` 쿼리가 없거나 잘못되어도 Step5가 정상 복구되는지
6. 위 동작 중에도 compare surface가 사라지지 않는지

이 문서는 일부러 아래 항목을 제외합니다.

- `recheck / finalize` 신뢰성 검증
- 상태별 기본 패널(`review_blocked`, `infeasible`, `solve_failed`)
- Step3 finalized 보호

위 3개는 각각 Slice6 또는 Slice8 문서에서 확인합니다.

## 2) 시작 전 준비

### 2.1 개발자/담당자가 먼저 준비할 것

QA 시작 전 아래 조건을 만족하는 테스트 월 1개를 준비합니다.

| 별칭      | 필수 상태                         | 왜 필요한가                                     |
| --------- | --------------------------------- | ----------------------------------------------- |
| `S7-BASE` | 같은 월 안에 버전이 2개 이상 존재 | preview 전환과 explicit select를 보기 위해 필요 |
| `S7-BASE` | 현재 `selected version`이 존재    | 쿼리 정규화 기준점이 있어야 함                  |
| `S7-BASE` | `finalized version`은 없음 권장   | Slice7 가이드는 finalized 동작을 보지 않음      |

담당 개발자가 QA에게 꼭 전달해야 하는 정보:

- 어떤 월 카드가 `S7-BASE`인지
- 해당 월에서 적어도 2개의 버전 카드가 보여야 한다는 점
- 가능하면 처음 진입 시 `미리보기`와 `선택됨`이 다른 버전으로 보이게 준비할 것

### 2.2 테스터가 준비할 것

1. 테스트 계정으로 로그인합니다.
2. 브라우저 주소창을 직접 수정할 수 있어야 합니다.
3. 같은 브라우저 탭에서만 테스트합니다.

## 3) 공통 진입 방법

아래 순서로 Step5에 들어갑니다.

1. 로그인 후 대시보드(`/`)로 이동합니다.
2. 담당 개발자가 지정한 `S7-BASE` 월 카드를 찾습니다.
3. 카드의 빈 영역을 클릭해서 Step5로 들어갑니다.
   - `수정` 버튼이 아니라 카드 본문 클릭입니다.
4. Step5가 열리면 현재 URL을 메모합니다.
   - 예: `/schedule/step5/<scheduleId>?version=<previewVersionId>`
5. 화면 상단에 아래 3개가 보이는지 먼저 확인합니다.
   - `버전 비교`
   - `미리보기 버전`
   - `선택된 버전`

## 4) 실행 카드

### 카드 A. Review Hub Shell 첫 화면 확인

목적: Slice7에서 Step5가 단일 결과 화면이 아니라 review hub shell로 바뀌었는지 확인

실행:

1. 공통 진입 방법대로 Step5를 엽니다.
2. 상단에서 `버전 비교` 제목이 있는 박스를 찾습니다.
3. 그 아래에 버전 카드가 2개 이상 보이는지 확인합니다.
4. 오른쪽 또는 아래쪽 action area에서 `미리보기 버전`과 `선택된 버전` 요약 박스를 확인합니다.

기대 결과:

- `버전 비교` 영역이 보입니다.
- 버전 카드가 2개 이상 보입니다.
- 어떤 카드에는 `미리보기` 칩이 보입니다.
- 어떤 카드에는 `선택됨` 칩이 보입니다.
- compare 영역은 grid 위에 있고, 숨겨져 있지 않습니다.

실패로 기록할 예:

- Step5는 열렸지만 `버전 비교` 영역이 아예 없음
- 버전 카드가 1개만 보여 preview/selected 분리를 확인할 수 없음
- `미리보기 버전`/`선택된 버전` 요약이 없음

### 카드 B. 정상 deep-link 유지 확인

목적: 유효한 `?version=` 값이 있으면 preview deep-link가 유지되는지 확인

사전조건:

- 현재 Step5 URL에 `?version=`이 있어야 합니다.

실행:

1. 현재 URL의 `version` 값을 확인합니다.
2. 페이지를 새로고침합니다.
3. 새로고침 후에도 같은 버전 카드에 `미리보기` 칩이 남아 있는지 확인합니다.

기대 결과:

- 새로고침 후 Step5가 에러 없이 다시 열립니다.
- `미리보기` 칩이 같은 버전에 남아 있습니다.
- `선택됨` 칩은 자동으로 다른 카드로 옮겨가지 않습니다.

실패로 기록할 예:

- 새로고침 후 다른 버전이 임의로 `미리보기`가 됨
- 쿼리가 살아 있는데 preview가 초기화됨

### 카드 C. 쿼리 없는 Step5 URL 자동 복구 확인

목적: `?version=`이 없는 legacy URL을 앱이 정상 정규화하는지 확인

실행:

1. 주소창에서 `?version=...` 부분만 지웁니다.
   - 예: `/schedule/step5/<scheduleId>`
2. Enter를 눌러 다시 진입합니다.
3. 페이지가 다시 열린 뒤 주소창을 확인합니다.

기대 결과:

- 빈 화면이나 에러 화면이 나오지 않습니다.
- 주소창에 다시 `?version=<무언가>`가 붙습니다.
- `미리보기`는 backend의 `selected version` 또는 기본 `V1`로 자동 복구됩니다.
- compare surface는 계속 보입니다.

실패로 기록할 예:

- 쿼리가 없으면 Step5가 깨짐
- URL은 복구됐지만 `버전 비교`가 사라짐

### 카드 D. 잘못된 쿼리 자동 복구 확인

목적: 존재하지 않는 `?version=` 값이 들어와도 앱이 정상 복구하는지 확인

실행:

1. 주소창의 `version` 값을 임의 문자열로 바꿉니다.
   - 예: `?version=not-a-real-version`
2. Enter를 눌러 다시 진입합니다.
3. 주소창과 화면을 함께 확인합니다.

기대 결과:

- Step5가 에러 없이 다시 열립니다.
- 주소창의 잘못된 값은 정상 버전 ID로 교체됩니다.
- `미리보기`는 backend `selected version` 또는 `V1`로 복구됩니다.
- compare surface는 그대로 보입니다.

실패로 기록할 예:

- 잘못된 version 값 때문에 빈 화면이 됨
- 잘못된 값이 URL에 그대로 남아 있음

### 카드 E. 버전 카드 클릭 시 preview만 변경되는지 확인

목적: Slice7 핵심 규칙인 `preview와 selected 분리`를 확인

실행:

1. 현재 `선택됨`이 붙어 있지 않은 다른 버전 카드를 찾습니다.
2. 그 카드를 1번 클릭합니다.
3. `미리보기` 칩이 어디로 이동했는지 확인합니다.
4. `선택됨` 칩이 원래 카드에 그대로 남아 있는지 확인합니다.
5. action area의 `미리보기 버전`/`선택된 버전` 요약도 같이 봅니다.

기대 결과:

- 클릭한 카드로 `미리보기`만 이동합니다.
- `선택됨`은 원래 카드에 그대로 남습니다.
- 화면 상단 compare surface는 사라지지 않습니다.
- 이 단계에서는 확정 후보가 바뀌지 않습니다.

실패로 기록할 예:

- 카드 클릭만으로 `선택됨`까지 같이 이동함
- 클릭 후 compare surface가 다시 그려지지 않음

### 카드 F. explicit select 버튼으로만 selected가 바뀌는지 확인

목적: authoritative selection이 명시적 CTA를 통해서만 바뀌는지 확인

사전조건:

- 카드 E를 통과해서 `미리보기`와 `선택됨`이 서로 다른 버전에 있어야 합니다.

실행:

1. action area의 기본 버튼 라벨이 `이 버전을 선택`인지 확인합니다.
2. 그 버튼을 1번 클릭합니다.
3. 버튼 동작이 끝난 뒤 compare surface를 다시 확인합니다.
4. 방금 `미리보기`였던 카드에 `선택됨` 칩이 붙는지 확인합니다.

기대 결과:

- 버튼을 누르기 전까지는 `선택됨`이 바뀌지 않습니다.
- 버튼을 누른 뒤에만 `선택됨`이 현재 `미리보기` 카드로 이동합니다.
- URL의 `version` 값은 현재 미리보기 값을 유지합니다.
- compare surface는 계속 보입니다.

실패로 기록할 예:

- 버튼 없이 카드 클릭만으로 selected가 바뀜
- 버튼 클릭 후에도 selected가 그대로임

## 7) 이번 문서 범위 밖(정상)

아래 항목은 이 문서에서 Fail로 판단하지 않습니다.

- `재검토 필요`, `하드 제약 위반 요약`, `생성 불가`, `생성 실패` 패널 완성도
- `다시 검토`, `이 버전 확정`, `다시 생성` 버튼 동작
- Step3에서 finalized month 저장 차단

위 항목은 Slice8 문서에서 봅니다.
