# P9-2.1: Admin Dashboard IA and Chart Composition

## Route and Ownership

| Route              | Component                                | Allowed Access States              |
| ------------------ | ---------------------------------------- | ---------------------------------- |
| `/dashboard/admin` | `src/views/dashboard/AdminDashboard.vue` | `['super_active', 'admin_active']` |

This document fixes the page-level information architecture for the admin dashboard.
It inherits metric/filter semantics from `docs/specs/p9/P9-1.1-dashboard-metrics-filter-spec.md`
and converts them into a concrete screen shell.

## Scope

`P9-2.1` decides:

- admin dashboard section order
- which metric surfaces use summary cards, comparison bars, and table views
- super/admin scope-selection placement
- loading, blocked, empty, and error states
- inclusion of the legacy schedule list/create entry inside the same route

`P9-2.1` does not decide:

- employee dashboard calendar UX (`P9-2.2`)
- URL persistence policy for filters (`P9-2.3`)
- export/download UX (`P9-3.x`)

## Shell IA

The admin dashboard is a single page with five vertical zones.


## Chart / Table Decision

No external chart library is required in `P9-2.1`.

Use:

- summary cards for aggregate fairness signals
- horizontal comparison bars for quick ranking/scanning
- `NDataTable` for exact numeric verification

Rationale:

- fairness metrics have small row counts in MVP and do not justify chart-library overhead
- `employee` and `site` groupings share the same numeric structure
- later filter E2E work can validate visible numbers against the same table surface

## Section Details

### 1. Header / Context

- Title: `관리자 대시보드`
- Subtitle explains that the page combines fairness analytics and schedule operations
- Context chips show:
  - access scope (`슈퍼 관리자` or `조직 관리자`)
  - current organization
  - current grouping (`직원 기준` or `사이트 기준`)

### 2. Filter Bar

- `organizationId`
  - visible only for `super_active`
  - placed first in the filter bar
  - when unresolved, the page remains accessible but analytics stay in `blocked` state
- `periodMonth`
  - always visible
  - single-select month list
- `siteId`
  - visible only when `siteFilterVisible === true`
- `rankId`
  - hidden when unsupported
- `grouping`
  - admin-only segmented toggle
  - values: `employee`, `site`
- `refresh`
  - right-aligned action button that reruns analytics fetch

## State Contract

### Loading

- Target Route: `/dashboard/admin`
- Exact UI Surface: fairness summary card area, analytics area, schedule operations card
- User Action: route entry or explicit refresh
- Expected Result:
  - filter bar remains visible
  - analytics area shows loading skeleton/spinner
  - schedule operations area shows list loading state independently

### Blocked

- Target Route: `/dashboard/admin`
- Exact UI Surface: `organization selector panel`
- User Action: `super_active` user opens `/dashboard/admin` without a selected organization
- Expected Result:
  - route stays on `/dashboard/admin`
  - organization selector is shown prominently
  - fairness cards/charts do not render misleading zero values

### Empty

- Target Route: `/dashboard/admin`
- Exact UI Surface: fairness analytics placeholder card
- User Action: select a `periodMonth` with no persisted finalized schedule
- Expected Result:
  - route stays on `/dashboard/admin`
  - analytics area shows empty guidance
  - schedule operations section still offers `새 근무표 생성`

### Error

- Target Route: `/dashboard/admin`
- Exact UI Surface: analytics alert banner
- User Action: RPC fetch failure
- Expected Result:
  - filter bar remains interactive
  - error alert explains the failed analytics load
  - schedule operations section remains usable when organization context exists

## Comparison Area Rules

### Grouping = `employee`

Bar labels and table rows show:

- employee name
- site name
- rank name
- `nightShiftCount`
- `weekendWorkCount`

### Grouping = `site`

Bar labels and table rows show:

- site name
- `nightShiftCount`
- `weekendWorkCount`

## Schedule Operations Rules

The former `src/views/Dashboard.vue` schedule list is not treated as a separate product surface.
Inside `/dashboard/admin`, it becomes the `schedule operations` section with:

- `새 근무표 생성` CTA
- schedule card list
- per-row actions: view, edit, delete
- onboarding deep-link compatibility banner and create-modal auto-open behavior

## Downstream Handoff

`P9-2.2` must preserve:

- header + filter bar visual hierarchy
- analytics block above the employee-specific calendar block
- shared empty/error language patterns

`P9-2.3` must preserve:

- filter field order: organization, period, site, grouping
- organization selector as page-level scope control, not a local table filter
