# P9-1.1: Dashboard Metrics and Filter Specification

## Scope

This document fixes the product and implementation contract for:

- dashboard route split and post-auth landing behavior
- fairness metric definitions for admin and employee dashboards
- filter behavior, defaults, and unsupported states
- role-specific visibility and dependency states that later tasks must honor

This task does **not** decide:

- DB vs RPC vs Edge Function aggregation boundary
- final chart library or component layout
- TypeScript implementation details beyond the public contract needed by `P9-1.2` and `P9-1.3`

## Route and Access Contract

### Canonical Routes

| Route                 | Purpose                                                       | Intended meta.roles          | Effective accessState                         |
| --------------------- | ------------------------------------------------------------- | ---------------------------- | --------------------------------------------- |
| `/dashboard/admin`    | Organization fairness dashboard + schedule operations surface | `['super', 'admin']`         | `super_active`, `admin_active`                |
| `/dashboard/employee` | Personal calendar + team comparison dashboard                 | `['super', 'admin', 'user']` | `super_active`, `admin_active`, `user_active` |

### Post-Auth Landing

| AccessState                 | Landing                                     |
| --------------------------- | ------------------------------------------- |
| `super_active`              | `/dashboard/admin`                          |
| `admin_active`              | `/dashboard/admin`                          |
| `user_active`               | `/dashboard/employee`                       |
| `admin_pending`             | existing blocked route (`/access/pending`)  |
| `admin_rejected`            | existing blocked route (`/access/rejected`) |
| `no_membership_or_inactive` | `/login`                                    |

> Decision: P9 makes dashboard routes the canonical active-user home. The current `POST_AUTH_REDIRECT_PATH = '/schedule/step1'` is a temporary pre-P9 baseline and must be replaced by the mapping above when dashboard routing is implemented.

### Existing Dashboard Transition

- The current `src/views/Dashboard.vue` schedule list and "새 근무표 생성" entry point are absorbed into `/dashboard/admin`.
- This surface is part of the admin dashboard's `schedule operations` section.
- Creating a separate `/schedules` route is out of scope for `P9-1.1`.

## Public Contract for P9-1.2 / P9-1.3

```typescript
type DashboardScope = 'admin' | 'employee';
type DashboardGrouping = 'employee' | 'site';

interface DashboardFilters {
  periodMonth: string;
  siteId?: string | null;
  rankId?: string | null;
}

interface AdminDashboardScopeSelector {
  organizationId?: string | null;
  grouping: DashboardGrouping;
}
```

Rules:

- `periodMonth` is the only required common filter.
- `siteId` and `rankId` are optional and omitted when unsupported or unselected.
- `organizationId` is a **super-only** scope selector, not a common filter.
- `grouping` is an admin-only view switch between employee and site slices.

## Metric Definitions

### Core Semantics

- The dashboard operates on **persisted schedule assignments** only.
- All metric calculations are evaluated within the selected `periodMonth`.
- Empty cells and deleted/unpersisted draft state do not count.
- Shift code semantics:
  - `N` = night shift
  - `D`, `E`, `N` = working shifts
  - `O` = off and excluded from work-count metrics

### Admin Dashboard Metrics

| Metric ID                           | Label               | Definition                                                                                                         | Grouping           | Visible To       |
| ----------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------ | ---------------- |
| `nightShiftCount`                   | 야간 근무 횟수      | Count assignments where `shift.code = 'N'` within `periodMonth` and current scope                                  | `employee`, `site` | `super`, `admin` |
| `weekendWorkCount`                  | 주말 근무 횟수      | Count assignments on Saturday or Sunday where `shift.code in ('D','E','N')` within `periodMonth` and current scope | `employee`, `site` | `super`, `admin` |
| `nightShiftAvg`                     | 평균 야간 근무      | Average `nightShiftCount` across the current grouping set                                                          | summary only       | `super`, `admin` |
| `nightShiftMin` / `nightShiftMax`   | 최소/최대 야간 근무 | Min / max `nightShiftCount` across the current grouping set                                                        | summary only       | `super`, `admin` |
| `nightShiftGap`                     | 야간 근무 편차      | `nightShiftMax - nightShiftMin` across the current grouping set                                                    | summary only       | `super`, `admin` |
| `weekendWorkAvg`                    | 평균 주말 근무      | Average `weekendWorkCount` across the current grouping set                                                         | summary only       | `super`, `admin` |
| `weekendWorkMin` / `weekendWorkMax` | 최소/최대 주말 근무 | Min / max `weekendWorkCount` across the current grouping set                                                       | summary only       | `super`, `admin` |
| `weekendWorkGap`                    | 주말 근무 편차      | `weekendWorkMax - weekendWorkMin` across the current grouping set                                                  | summary only       | `super`, `admin` |

Grouping rules:

- `employee`: fairness comparison across included employees
- `site`: fairness comparison across included sites using the same base counts

### Employee Dashboard Metrics

| Metric ID               | Label             | Definition                                                              | Visible To                                 |
| ----------------------- | ----------------- | ----------------------------------------------------------------------- | ------------------------------------------ |
| `myNightShiftCount`     | 내 야간 근무 횟수 | The signed-in employee's `nightShiftCount` in the selected scope        | `super`, `admin`, `user` via employee view |
| `myWeekendWorkCount`    | 내 주말 근무 횟수 | The signed-in employee's `weekendWorkCount` in the selected scope       | `super`, `admin`, `user` via employee view |
| `teamNightShiftAvg`     | 팀 평균 야간 근무 | Average `nightShiftCount` of the comparison team in the selected scope  | `super`, `admin`, `user` via employee view |
| `teamWeekendWorkAvg`    | 팀 평균 주말 근무 | Average `weekendWorkCount` of the comparison team in the selected scope | `super`, `admin`, `user` via employee view |
| `myCalendarAssignments` | 개인 월간 일정    | Persisted daily assignments for the signed-in employee in `periodMonth` | `super`, `admin`, `user` via employee view |

Comparison team rules:

- For `user_active`, the team is the user's accessible organization scope after optional `siteId` / `rankId` filters.
- For `admin_active` and `super_active` visiting the employee dashboard, the view behaves as an employee-perspective page with the same metric semantics.

## Filter Contract

### Common Filters

| Field         | Type           | Required | Default                                                            | Visibility                                                                    | Behavior                                 |
| ------------- | -------------- | -------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- | ---------------------------------------- |
| `periodMonth` | `YYYY-MM`      | Yes      | latest accessible persisted schedule month, fallback current month | always shown                                                                  | single-month selector only               |
| `siteId`      | UUID \| `null` | No       | `null` (`all`)                                                     | shown only when organization has 2+ usable sites                              | narrows metrics and calendar to one site |
| `rankId`      | UUID \| `null` | No       | `null` (`all`)                                                     | shown only when rank master exists **and** employee-rank mapping is available | narrows metrics and calendar to one rank |

### Admin-Only Scope Controls

| Field            | Type                   | Required   | Default                                                                           | Visible To                          | Behavior                                                                   |
| ---------------- | ---------------------- | ---------- | --------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------- |
| `organizationId` | UUID \| `null`         | super only | previously selected org if available, otherwise unresolved until user selects one | `super` on admin dashboard          | prevents implicit all-org aggregation                                      |
| `grouping`       | `'employee' \| 'site'` | Yes        | `'employee'`                                                                      | `super`, `admin` on admin dashboard | switches the comparison dimension without changing base metric definitions |

Rules:

- `admin_active` does not choose `organizationId`; own organization is implicit.
- `user_active` never sees `organizationId` or `grouping`.
- `rankId` is hidden rather than disabled when unsupported.
- `siteId` is hidden rather than disabled when there is only one usable site.

## Role-Specific Surface Rules

### Admin Dashboard

- `super_active`
  - can view `/dashboard/admin`
  - must choose an organization scope before metrics load if no current org selection exists
  - can switch grouping between `employee` and `site`
- `admin_active`
  - can view `/dashboard/admin`
  - organization scope is fixed to the effective membership organization
  - can switch grouping between `employee` and `site`
- `user_active`
  - cannot view `/dashboard/admin`

### Employee Dashboard

- `user_active`
  - can view `/dashboard/employee`
  - sees personal calendar and personal/team metrics only
- `admin_active` / `super_active`
  - can view `/dashboard/employee`
  - the page is still employee-perspective, not an admin analytics page

## Dependency and Empty States

### No Persisted Schedule Data

- If no persisted schedule exists for `periodMonth`, both dashboards show an empty state rather than zeroed fairness charts.
- Empty-state message should direct admins to create a schedule and users to switch month if applicable.

### Missing Employee Mapping

- Personal employee metrics require a resolved employee row linked to the signed-in account (`employees.user_id = auth.uid()` or equivalent resolved mapping).
- If that mapping is missing:
  - `/dashboard/employee` remains accessible
  - the page shows a dependency state instead of a permission error
  - team-level comparison and personal calendar do **not** load

### Missing Rank Mapping

- If rank master data exists but employee-rank mapping is not yet available in the app/domain layer:
  - `rankId` is hidden
  - API requests omit `rankId`
  - this is treated as unsupported scope, not as a failed query
