# P5-1.4: Organization Management Test Scenarios

## Role × Operation Matrix

### Organization Info

| Scenario                           | super          | admin (own org) | user         |
|------------------------------------|----------------|-----------------|--------------|
| View organization list             | All orgs       | Own org only    | Redirect `/` |
| View organization info             | Any org        | Own org         | Blocked      |
| Update name/type                   | Any org        | Own org         | 403/blocked  |
| Direct URL `/admin/organization`   | Allowed        | Allowed         | Guard → `/`  |
| Try accessing other org's settings | N/A (all orgs) | RLS → empty     | Blocked      |

## Tenant Isolation Scenarios

1. **Admin A requests Org B's settings**: RLS `has_org_access(org_id, 'admin')` returns false → empty result
2. **Malicious `organization_id` in POST body**: Supabase RLS ignores the insert → 0 rows affected or permission denied
3. **Super reads all orgs**: `is_super_admin()` → true → bypasses org filter
4. **User with pending membership tries admin page**: `accessState === 'admin_pending'` → route guard blocks → redirect to `/`

## CRUD Validation Scenarios

### Shifts
- Valid data → created, appears in list
- Duplicate `code` → error: "이미 존재하는 시프트 코드입니다"
- FK reference exists → delete blocked with Korean message
- Code with lowercase input → auto-uppercased before save

### Sites
- Same CRUD pattern as shifts
- Delete blocked if `site_staffing_requirements` or `employee_site_assignments` reference exists

### Skills / Ranks
- Duplicate code → 23505 error → Korean message
- Delete blocked if referenced in `employee_skills` / `site_staffing_requirements`
