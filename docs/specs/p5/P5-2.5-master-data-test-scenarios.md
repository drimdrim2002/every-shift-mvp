## Skills + Sites Delete Cascade Analysis

| FK table                           | ON DELETE action  | Blocks delete? |
|------------------------------------|-------------------|----------------|
| employee_skills.skill_id           | CASCADE           | No (deletes rows) |
| site_staffing_requirements.skill_id| SET NULL          | No             |
| employee_site_assignments.site_id  | CASCADE           | No (deletes rows) |
| site_staffing_requirements.site_id | CASCADE           | No (deletes rows) |

> **Conclusion**: The DB schema uses CASCADE/SET NULL for most FKs. The "사용 중이어서 삭제할 수 없습니다" error will only fire from `error.code === '23503'` if there are remaining RESTRICT-type FKs. For a better UX, the UI should check for references before deleting and show a confirmation dialog listing affected records.
