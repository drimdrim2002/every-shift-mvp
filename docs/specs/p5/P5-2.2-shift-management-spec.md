# P5-2.2: Shift Management Specification

## Summary

- Admin shift CRUD is implemented inside `/admin/organization` and uses an admin-local modal boundary.
- The current operationally compatible shift contract remains `D/E/N/O`.
- Additional shift codes may be stored in the shift master, but Step wizard, planning payload generation, and result aggregation still treat `D/E/N/O` as the only fully supported runtime set until P7.

## Field Contract

| Field        | Type            | Required    | Rule                                               |
| ------------ | --------------- | ----------- | -------------------------------------------------- |
| `code`       | UI: `1-2` chars | YES         | Uppercase alphanumeric, unique within organization |
| `name`       | `VARCHAR(50)`   | YES         | Trimmed free text, max 50 chars                    |
| `color_code` | `#RRGGBB`       | YES         | Stored as 6-digit hex                              |
| `start_time` | `HH:mm`         | conditional | Required for timed shifts, null for `O`            |
| `end_time`   | `HH:mm`         | conditional | Required for timed shifts, null for `O`            |

## Validation Rules

- `code` is normalized to uppercase before save.
- Duplicate `code` is rejected at both UI and API boundaries.
- `O` must keep both `start_time` and `end_time` empty.
- Timed shifts must provide both `start_time` and `end_time`.
- Overnight shifts are allowed.
- Identical `start_time` and `end_time` are rejected.
- Editing flow keeps `code` immutable after creation.

## Delete Contract

- `deleteShift` no longer deletes dependent rows first.
- Deletion is blocked when the shift is referenced by:
  - `site_requirements`
  - `site_staffing_requirements`
  - `schedule_assignments`
- The API returns a Korean blocking message that names the referencing domains.
- Local migration `014_restrict_shift_delete_from_staffing_requirements.sql` aligns the `site_staffing_requirements.shift_id` FK with the blocking policy.

## UI Boundary

- Admin route uses `src/components/admin/ShiftManagementModal.vue`.
- Existing `src/components/schedule/ShiftManager.vue` remains the onboarding and Step1 modal boundary for now.
- Preview rows in `OrganizationManagement.vue` are display-only and cannot be edited or deleted.

## Explicit Non-Goals

- `ShiftSelector.vue` dynamic runtime refactor
- Solver payload/runtime expansion beyond `D/E/N/O`
- Step2/Step5 aggregation changes for arbitrary shift codes

Those remain P7 work items.
