# P5-2.2: Shift Management Specification

## Field Definitions

| Field       | Type           | Required | Validation                              |
|-------------|----------------|----------|-----------------------------------------|
| code        | VARCHAR(5)     | YES      | Uppercase alphanumeric 1–5 chars, org-unique |
| name        | VARCHAR(50)    | YES      | Free text, max 50 chars                 |
| color_code  | VARCHAR(7)     | YES      | Hex color: `#RRGGBB`                    |
| start_time  | TIME (HH:MM)   | NO       | Null allowed for Off shifts             |
| end_time    | TIME (HH:MM)   | NO       | Null allowed for Off shifts; both must be null or both set |

## DB Constraints

- `UNIQUE (organization_id, code)` — enforced at DB level (error code 23505)
- `code` is stored uppercase — `shift.ts:createShift` calls `.toUpperCase()` before insert

## Validation Rules (frontend)

```typescript
function validateShiftCode(code: string): string | null {
  if (!code) return '시프트 코드를 입력해주세요'
  if (!/^[A-Z0-9]{1,5}$/.test(code.toUpperCase())) {
    return '코드는 대문자 영숫자 1~5자여야 합니다'
  }
  return null
}

function validateShiftTimes(start: string | null, end: string | null): string | null {
  if ((start === null) !== (end === null)) {
    return '시작 시간과 종료 시간을 모두 입력하거나 모두 비워주세요'
  }
  return null
}
```

## Delete Policy Change

**Current behavior** (`src/api/shift.ts:deleteShift`): cascade-deletes `site_requirements` and `schedule_assignments` first, then deletes the shift.

**Target behavior** (P5 spec): Block deletion if FK references exist. Return Korean error.

> ⚠️ This is a **breaking behavior change** in `deleteShift`. Update in P6/P7 when the cascade behavior is confirmed unnecessary. Mark as a known delta for now.

## Impact on ShiftSelector.vue

`src/components/schedule/ShiftSelector.vue` currently hardcodes D/E/N/O buttons. After shift management is live, it must be refactored to read from `orgStore.shifts` dynamically. This refactor is deferred to **P7** when Solver Integration begins.
