# P5-1.2: Organization Management Routes & IA

## Route Decision: Single Page + NTabs

Instead of 6 separate routes, a **single route with NTabs** is used to reduce route guard duplication and simplify breadcrumbs.

| Route                 | Component                    | Guard                                                   |
| --------------------- | ---------------------------- | ------------------------------------------------------- |
| `/admin/organization` | `OrganizationManagement.vue` | `allowedAccessStates: ['super_active', 'admin_active']` |

> Canonical reference: `P5-1.1`. Older notes that mention `meta.roles` or
> `/admin/organizations` are legacy references and must not drive implementation.

## Sidebar Menu

Add to `src/components/layout/Sidebar.vue`:

```typescript
// Show only when accessState is 'super_active' or 'admin_active'
{
  label: '조직 관리',
  key: '/admin/organization',
}
```

Visibility rule:

- show for `super_active`
- show for `admin_active`
- hide for `user_active`, `admin_pending`, `admin_rejected`

## Super Admin: Org Selector

When `accessState === 'super_active'`, render an `NSelect` dropdown at the top of `OrganizationManagement.vue` to switch between organizations. Admin users see only their own organization without a selector.

## Route Registration (in `src/router/index.ts`)

Add inside the authenticated `'/'` children array:

```typescript
{
  path: 'admin/organization',
  name: 'AdminOrganization',
  component: () => import('@/views/admin/OrganizationManagement.vue'),
  meta: {
    title: '조직 관리',
    requiresAuth: true,
    allowedAccessStates: ['super_active', 'admin_active'],
  },
},
```

## Route Guard Logic

The current router already resolves `allowedAccessStates` from matched records.
This feature should plug into that existing contract rather than adding a new
`meta.roles` path.

Guard behavior:

- `super_active` -> allowed
- `admin_active` -> allowed
- `admin_pending` -> redirected by existing blocked-state logic to `/access/pending`
- `admin_rejected` -> redirected by existing blocked-state logic to `/access/rejected`
- `user_active` -> redirected by the existing `resolvePostAuthRedirectPath()` flow
- unauthenticated -> redirected to `/login`

```typescript
meta: {
  title: '조직 관리',
  requiresAuth: true,
  allowedAccessStates: ['super_active', 'admin_active'],
}
```

## Scope Notes

- `P5-1.2` defines only the page shell, route, menu entry, and tab container.
- It does not introduce a separate create/delete organization route.
- It does not implement save logic ahead of `P5-1.3`.
