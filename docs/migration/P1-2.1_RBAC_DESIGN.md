# P1-2.1 RBAC 판별 로직 및 헬퍼 함수 설계

본 문서는 EveryShift 서비스 전환을 위한 RBAC(Role-Based Access Control) 판별 로직과 데이터베이스 수준의 헬퍼 함수 설계 내용을 담고 있습니다.

## 1. 역할 정의 및 권한 범위

### 1.1 전역 역할 (Global Role)
`profiles.global_role` 컬럼을 기준으로 시스템 전체에 대한 권한을 정의합니다.

| 역할 | 설명 | 권한 범위 |
| :--- | :--- | :--- |
| **super** | 시스템 최고 관리자 | 모든 조직 데이터 접근 가능, RLS 우회 |
| **admin** | 일반 관리자 | 소속 조직에 대한 관리 권한 (조직 멤버십 승인 필요) |
| **user** | 일반 사용자 | 소속 조직의 일반 기능 접근 (조직 멤버십 승인 필요) |

### 1.2 조직 역할 (Organization Role)
`organization_memberships.role` 컬럼을 기준으로 특정 조직 내에서의 권한을 정의합니다.

| 역할 | 설명 | 권한 범위 |
| :--- | :--- | :--- |
| **admin** | 조직 관리자 | 소속 조직의 직원, 설정, 스케줄 관리 |
| **user** | 조직 구성원 | 본인 스케줄 조회 및 제한된 정보 접근 |

## 2. 상태 기반 접근 제어 (Status-based Access Control)

### 2.1 계정 상태 (`profiles.account_status`)
- **active**: 정상 서비스 이용 가능
- **pending/rejected/suspended/withdrawn**: 서비스 접근 차단 (로그인 후 안내 화면만 노출)

### 2.2 멤버십 상태 (`organization_memberships.status`)
- **approved**: 해당 조직 데이터 접근 허용
- **pending**: 온보딩 위저드 외 데이터 접근 불가
- **rejected/withdrawn**: 해당 조직 데이터 접근 차단

## 3. RBAC 판별 로직 우선순위

1.  **전역 `super` 권한 확인**: `super`인 경우 모든 테넌트 격리를 우회하여 접근 허용.
2.  **계정 상태 확인**: `account_status`가 `active`가 아니면 모든 접근 차단.
3.  **조직 멤버십 확인**: `approved` 상태인 멤버십이 있는 조직의 데이터만 접근 허용.
4.  **조직 내 역할 확인**: 요청된 작업에 필요한 최소 역할(admin/user) 만족 여부 확인.

## 4. 데이터베이스 헬퍼 함수 설계

RLS 정책에서 효율적으로 권한을 검사하기 위해 `auth` 스키마 또는 `public` 스키마에 보안 함수를 정의합니다. (본 프로젝트에서는 `auth` 확장을 고려하여 `public` 또는 별도 보안 스키마 검토)

### 4.1 `public.is_super_admin()`
- **목적**: 현재 사용자가 `super` 관리자인지 확인
- **반환**: `BOOLEAN`
- **로직**: `profiles` 테이블에서 `auth.uid()`와 일치하는 행의 `global_role`이 'super'인지 확인

### 4.2 `public.get_my_org_role(target_org_id UUID)`
- **목적**: 특정 조직에 대한 사용자의 역할과 상태를 조회
- **반환**: `JSONB` `{ "role": "admin|user", "status": "approved|pending|..." }`
- **로직**: `organization_memberships` 테이블에서 `user_id = auth.uid()` 및 `organization_id = target_org_id`인 행 조회

### 4.3 `public.has_org_access(target_org_id UUID, min_role TEXT)`
- **목적**: RLS 정책에서 한 줄로 권한을 검사하기 위한 통합 함수
- **반환**: `BOOLEAN`
- **로직**:
    1.  `is_super_admin()` 이면 `TRUE`
    2.  `account_status`가 `active`가 아니면 `FALSE`
    3.  `organization_memberships`에서 `status = 'approved'` 이고 `role`이 `min_role`의 권한을 충족하면 `TRUE`

## 5. RLS 적용 예시

```sql
-- 예: schedules 테이블 RLS
CREATE POLICY "조직 관리자 및 구성원 접근 허용"
ON schedules
FOR ALL
USING (
  public.has_org_access(organization_id, 'user')
);
```
