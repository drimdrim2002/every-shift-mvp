### 4.1 Pre-check 쿼리

| ID | 목적 | 통과 기준 |
| :--- | :--- | :--- |
| PRE-01 | 핵심 테이블 row count 스냅샷 고정 | 스냅샷 수치가 저장됨 |
| PRE-02 | 운영데이터 조직 식별 | 대상 조직 목록이 비어있지 않음 |
| PRE-03 | NULL 분포 및 백필 필요량 계산 | 필요량이 정량화됨 |
| PRE-04 | `site_requirements` vs `shifts` 조직 참조 무결성 | mismatch = 0 |
| PRE-05 | `schedule_assignments`의 schedule-employee 조직 일치 | mismatch = 0 |
| PRE-06 | `site_requirements` 중복 위험 검사 (`org/shift/day`) | duplicate row = 0 |
| PRE-07 | 필수/예상 인덱스 존재 점검 | `uq_site_requirements_scope` 존재 확인 + 누락 인덱스 기록 |
| PRE-08 | migration ledger 확인 | 현재 migration drift 상태 확인 가능 |
| PRE-09 | 문서 범위 검증 (`organizations.code/timezone` 미존재 확인) | 두 컬럼 모두 absent |

### 4.2 Post-check 쿼리

| ID | 목적 | 통과 기준 |
| :--- | :--- | :--- |
| POST-01 | 마스터 백필 완료성 (`organization_settings/sites/ranks/skills`) | 운영데이터 조직당 최소 1행 충족 |
| POST-02 | `site_staffing_requirements` 이관 건수 검증 | 대상 `site_requirements` 건수와 일치 |
| POST-03 | `schedule_assignments.site_id` 채움 검증 | 대상 조직 NULL 건수 = 0 |
| POST-04 | 신규 참조 FK 무결성 검증 | orphan = 0 |
| POST-05 | `site_staffing_requirements` scope 중복 검증 | duplicate = 0 |
| POST-06 | 원본 `site_requirements` 보존 검증 | baseline 대비 row count 불변 |
| POST-07 | `employees.user_id` 정책 검증 (본 단계는 유지) | user_id 채움 강제 없음/현황 추적 가능 |

## 5) Known Drift (중요)

### 5.1 확인된 드리프트

1. migration ledger에는 `004_add_off_comment`만 기록됨
2. 실DB에는 007의 일부 스키마 객체가 존재함
3. 예상 인덱스 누락:
   - `uq_employees_org_user` 미확인
   - `uq_site_staffing_requirements_scope` 미확인

### 5.2 후속 작업 반영 지침

1. P1-3.2 실행 전 PRE-07/PRE-08을 반드시 재실행한다.
2. 누락 인덱스가 계속 미존재면 백필 SQL에 `NOT EXISTS` 기반 안전장치를 강화한다.
3. Drift 해소를 위한 DDL 보완은 별도 migration 또는 선행 태스크로 분리한다.

## 6) P1-3.2 인계 규격 (멱등 SQL 작성용)

후속 문서/SQL은 아래 구조를 그대로 따른다.

| field | 설명 |
| :--- | :--- |
| step_id | 실행 순번 (`B001`, `B002` ...) |

| source_query_id | source 집합 정의용 PRE query ID |

| idempotency_guard | `ON CONFLICT`, `NOT EXISTS`, `WHERE ... IS NULL` |

| rollback_note | 실패 시 복구/재실행 전략 |
